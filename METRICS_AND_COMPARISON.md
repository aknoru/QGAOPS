## 2. Arithmetic & Numerical Precision Metrics

The accelerator operates on the real 3-dimensional Euclidean Clifford Algebra $\mathcal{C}\ell(3,0)$, spanned by 8 canonical basis blades:
$$\mathbf{B} = \langle 1, \, e_1, \, e_2, \, e_3, \, e_{12}, \, e_{13}, \, e_{23}, \, e_{123} \rangle$$
where $e_1^2 = e_2^2 = e_3^2 = +1$ and $e_i e_j = -e_j e_i$ for $i \neq j$.

| Metric | Specification / Measured Value | Verification Method |

| **Algebra Metric** | Euclidean $\mathcal{C}\ell(3,0)$, signature $(+, +, +)$ | 64/64 basis-blade products verified |

| **Resolution / LSB** | $2^{-16} \approx 1.52588 \times 10^{-5}$ | Fixed-point quantization analysis |
| **Multiplication Rule** | 32-bit $\times$ 32-bit $\rightarrow$ 64-bit intermediate, right-shift 16 | Bit-exact signed arithmetic |
| **Overflow Handling** | Symmetric saturation clamping (`0x7FFFFFFF` / `0x80000000`) | Boundary injection vectors |
| **Numerical Fidelity** | **$1.0000$ (100.00% bit-exact across 2,360 / 2,360 blades)** | 295 physical FPGA hardware test vectors |

## 8. Head-to-Head Comparison: `SEQ_GPU` vs. `PARALLEL_GPU`

```
                      ┌─────────────────────────────────────────────────────────────┐
                      │              CL(3,0) ARCHITECTURAL COMPARISON               │
                      ├──────────────────────────────┬──────────────────────────────┤
                      │      SEQ_GPU (Sequential)    │   PARALLEL_GPU (Parallel)    │
                      ├──────────────────────────────┼──────────────────────────────┤
  EXECUTION PARADIGM  │ Iterative loop state machine │ Fully unrolled spatial tree  │
  DSP48E2 SLICES      │ 16 DSPs (1.28%)              │ 832 DSPs (66.67%)            │
  CLB LUTS            │ 15,238 LUTs (13.01%)         │ 39,809 LUTs (33.99%)         │
  CLB REGISTERS (FF)  │ 20,246 FFs (8.64%)           │ 28,108 FFs (12.00%)          │
  KERNEL CLOCK CYCLES │ 64 cycles / product          │ 1 cycle / product            │
  KERNEL LATENCY      │ 640 ns @ 100 MHz             │ 10 ns @ 100 MHz              │
  WORST NEG SLACK     │ +2.050 ns (relaxed)          │ +1.286 ns (tight routing)    │
  ON-CHIP POWER       │ 2.84 W                       │ 3.42 W                       │
  ENERGY / PRODUCT    │ 1.82 µJ                      │ 0.034 µJ (53.5× better)      │
  OPTIMAL FIT         │ Ultra-low-power edge IoT     │ Real-time 4K / Quantum Sim   │
                      └──────────────────────────────┴──────────────────────────────┘
```

### Detailed Structural Comparison:

| Architectural Feature | `SEQ_GPU` (Sequential Resource-Shared) | `PARALLEL_GPU` (Parallel Pipelined) |
| :--- | :--- | :--- |
| **Core Design Objective** | **Minimal Area & Low Power Footprint**: Designed to co-exist with other heavy accelerators in resource-constrained FPGA tiles. | **Maximum Throughput & Minimal Latency**: Consumes available DSP slices to deliver single-cycle multivector transformations. |
| **Arithmetic Datapath** | **Single Time-Shared MAC Unit**: Computes the 64 pairwise blade products using nested sequential loops (`for left=0..7`, `for right=0..7`) over 64 consecutive clock cycles. | **Spatial Binary Adder Trees**: 64 hardware multipliers execute simultaneously, feeding an 8-way balanced summation tree for all 8 output blades. |
| **Memory Fabric (AAMF)**| **Dual-Port Block RAMs**: Operands $A$ and $B$ are buffered in dual-port internal BRAMs (`int_a`, `int_b`), and results accumulate in `int_c`. Read/write pointers serialize data movement. | **Discrete Broadside Register Bank**: Operands are held in wide 256-bit broadside registers, directly feeding all 64 multiplier inputs without memory serialization. |
| **AXI Register Map** | Dense 4-byte packed layout: Base `0xA0000000`, Opcode `0x10`, A `0x20-0x3C`, B `0x40-0x5C`, C `0x60-0x7C`, Status `0x80`. | Stride-aligned high-throughput layout: A `0x10-0x48`, B `0x50-0x88`, C `0x90-0x100`, Opcode `0x110`, PL LEDs `0xA0040000`. |
| **Hardware Indicators**| PS MIO LEDs via `/sys/class/leds/ps_led0`. | **4 Physical Bank 66 PL User LEDs** (`B5`, `A6`, `B8`, `A7` @ `LVCMOS12`) driven directly by `axi_gpio_leds` @ `0xA0040000`. |
| **Timing Closure** | Extremely relaxed routing: **WNS = $+2.050\text{ ns}$**. | High routing density: **WNS = $+1.286\text{ ns}$** (achieved clean closure without timing exceptions). |
| **Trade-Off Verdict** | Superior for battery-powered IoT devices and background spatial tracking where low power trumps compute latency. | **Superior by 64.0× for kernel execution and 53.5× for energy efficiency**, essential for real-time vision, robotics kinematics, and quantum gate simulation. |
